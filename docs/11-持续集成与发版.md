# 11 · 持续集成与发版

本文记录 GitHub Actions 的构建方案，以及**为什么推送走 REST API 而不是 `git push`**。

仓库：`https://github.com/MRDOCTOROO/DoobleDouble`（私有）

---

## 1. 为什么需要 CI

本工程只有 **arm64-v8a / armeabi-v7a** 两个 ABI（Bcore 的 `libblackbox.so`
上游只出这两个）。本地出包要装齐：

| 组件 | 版本 |
|---|---|
| JDK | 17 |
| Android SDK platform | 35 |
| build-tools | 35.0.0 |
| NDK | 26.1.10909125 |
| CMake | 3.22.1 |

换台机器就得重来一遍。放到 CI 之后：

- 每次 push 自动产出**可直接安装**的 APK，手机浏览器就能下；
- 打 tag 自动发 Release，产物长期可访问（Actions artifact 只有 90 天）；
- 顺手跑 199 个单元测试，避免「本地绿、推上去红」。

## 2. ⚠️ 本机不能 `git push`：`github.com` 主站被挡

实测各域名（2026-09-29）：

| 域名 | 结果 | 说明 |
|---|---|---|
| `github.com` | **000** | 被代理挡住（`CONNECT tunnel failed, response 502`）——**`git push` 走的就是它** |
| `api.github.com` | 200 | 通 |
| `codeload.github.com` | 301 | 通 |
| `raw.githubusercontent.com` | 301 | 通 |
| `objects.githubusercontent.com` | 404 | 通（Release 产物下载走这里） |
| `uploads.github.com` | 302 | 通 |

绕过代理直连 `github.com` 也不行（`Could not connect to server`）。

**所以推送改成走 REST API**（`tools/gh-publish.py`）：

```
1. 从本地 git 对象库读 HEAD 的全部 blob（git cat-file --batch）
2. 逐个 POST /git/blobs            → 每个文件的 sha
3. POST /git/trees                 → 整棵树
4. POST /git/commits               → 提交（带父提交，支持增量）
5. POST/PATCH /git/refs/heads/main → 移动分支
```

好处：**推上去的内容与本地提交逐字节一致**，而且天然排除 `.gitignore` 里的东西
（读的是 git 对象，不是工作区目录）。

### 2.1 踩到的两个坑

**坑一：空仓库上 Git Data API 直接 409。**

```
POST /repos/{owner}/{repo}/git/blobs
HTTP 409: {"message":"Git Repository is empty."}
```

GitHub 要求仓库里**先有一个 ref** 才能建 blob / tree / commit。而且
`GET /git/ref/heads/main` 在空仓库上返回的是 **409 而不是 404** ——
只判 404 的代码会漏掉这种情况。

修法：先探分支，不存在就用 Contents API 写一个占位文件把 `refs/heads/main`
建出来，之后真正的推送把它当父提交。

**坑二：`git config --get credential.helper` 的值带引号。**

```
!"C:/Users/admin/.workbuddy-ai/binaries/PortableGit/versions/1.2.0/mingw64/bin/git-credential-wincred.exe"
```

前导 `!` 表示"这是 shell 命令"，外面还包了一层双引号（路径含空格时必需）。
Python 里 `subprocess.run([helper, ...])` 不会走 shell，路径带引号就
`FileNotFoundError` → 静默变成"找不到令牌"。

修法：`helper.lstrip("!").strip().strip('"').strip("'")`。

## 3. 签名：为什么必须用**固定**密钥

Android 只允许「同签名」的 APK 覆盖安装。而 **GitHub Actions 每次都是全新
runner**，`~/.android/debug.keystore` 是当场生成的 —— 也就是**每次签名都不同**。

用 debug 签名发版，用户装了第一版之后**再也装不上第二版**：

```
INSTALL_FAILED_UPDATE_INCOMPATIBLE
```

只能卸载重装，而卸载会清掉**所有空间、空间内应用、已登录的谷歌账号**。

所以本工程用固定的 release 密钥，且**密钥库不入库**：

| 位置 | 内容 |
|---|---|
| 本地 | `keystore/dooble-release.jks` + `keystore/keystore.properties`（整个目录在 `.gitignore` 里） |
| CI | GitHub Secrets 里的 `KEYSTORE_BASE64`，构建时解到 `$RUNNER_TEMP` 下 |

**为什么解到 `$RUNNER_TEMP` 而不是 `app/build/`**：`./gradlew clean` 会把
`app/build/` 整个删掉，密钥库跟着没。所以走 `DOOBLE_KEYSTORE_PATH`
环境变量指过去。

`app/build.gradle.kts` 的取值顺序：

```
DOOBLE_KEYSTORE_PATH（CI）  →  keystore/dooble-release.jks（本地）  →  不签名
```

第三个分支很重要：**两者都没有时不配置签名，产出未签名 APK 而不是构建失败**。
否则「clone 下来先跑一次 assembleDebug」的人会被卡住。

### 3.1 换机 / 轮换密钥

```bash
tools/gen-release-keystore.sh            # 已有则拒绝覆盖
tools/gen-release-keystore.sh --force    # 强制重建（会换签名，见下方警告）
python tools/gh-secrets.py --repo MRDOCTOROO/DoobleDouble
```

> **`--force` 的后果**：换密钥 = 换签名 = **老版本无法覆盖安装**。
> 已经装在设备上的用户必须卸载重装。除非密钥泄露，否则不要重建。

## 4. workflow 的关键取舍

### 4.1 不用 `android-actions/setup-android`

它会去装 Google 早已下架的 legacy `tools` 包，直接失败：

```
Warning: Failed to find package 'tools'
Error: The process '.../sdkmanager' failed with exit code 1
```

`ubuntu-latest` 镜像**本来就带完整 Android SDK**（含 cmdline-tools），直接用即可。

### 4.2 显式装 NDK / CMake，不让 AGP 自己下

不显式装的话，AGP 会在构建中途报 `NDK not configured`，或者自己下一个
**别的版本**，然后抛一堆看不懂的 native 错误。后者更难查。

### 4.3 `clean` 是必须的，不是洁癖

增量构建出来的 APK 比 clean 后大约 **4MB**（zipalign 对齐填充 + 残留本地头）。
量体积、发版前必须 clean，否则会误判成"代码变胖了"。

### 4.4 `full` 变体只在打 tag 时构建

`full` 会在构建时下载约 **108MB** 的 microG。每次 push 都做太浪费
（Actions 的 artifact 存储对免费账号有额度）。

### 4.5 验签 + 验 ABI

`Verify APK signature & ABIs` 这一步做两件事：

1. `apksigner verify --print-certs` —— 确认真的签上了（没配 Secret 时会明确提示）；
2. `unzip -l | grep 'lib/'` —— 确认**只有** `arm64-v8a` / `armeabi-v7a`。

第 2 条是硬要求：**APK 里一旦出现 `lib/x86_64/`**（哪怕只躺着一个第三方
`.so`），`primaryCpuAbi` 就会变成 x86_64，于是 `libblackbox.so` 永远找不到，
`attachBaseContext` 里抛 `UnsatisfiedLinkError` —— 表现为「引擎静默降级」，
极难归因。

## 5. ⚠️ Bcore 的 AAR 是入库的

`engine/libs/bcore.aar`（2.1MB）与 `black-reflection.jar` **必须入库**，
否则 CI 编译不出来。

重建它们需要：上游源码 `nbb-src` + JDK 21 + NDK 29 + 打 5 个补丁。
在 CI 里复现这套环境不划算，所以直接提交产物。

> **改补丁之后必须同步提交新的 AAR**：
> ```bash
> tools/build-bcore.sh
> git add engine/libs/bcore.aar engine/libs/black-reflection.jar
> ```
> 否则 CI 用的还是旧引擎 —— 会出现「本地好的、CI 出来的坏了」这种最难查的问题。

`.gitignore` 里为此写了例外规则，注意**顺序**（gitignore 是后面的规则覆盖前面的）：

```
/engine/libs/*.aar
/engine/libs/*.jar
!/engine/libs/bcore.aar
!/engine/libs/black-reflection.jar
```

## 6. 日常用法

### 拉最新代码出包

```bash
git clone https://github.com/MRDOCTOROO/DoobleDouble.git   # 需要能访问 github.com
# 或者继续用本机的 API 推送脚本
```

### 手动触发一次构建

网页：Actions → Android → Run workflow
（勾 `build_full` 可同时出 full 变体）

### 发版

```bash
git tag v0.2.0 && git push origin v0.2.0   # 需要能访问 github.com
```

打 tag 后 workflow 会：跑测试 → 构建 lite + full → **自动创建 Release 并把
APK 挂上去**，Release 说明里带安装指引。

### 手机下载

私有仓库需要在那台设备上登录 GitHub。直接开
`https://github.com/MRDOCTOROO/DoobleDouble/releases` 下载即可。

> 如果觉得每次登录麻烦，可以把仓库改成公开 —— 但**公开仓库的历史无法撤回**，
> 一旦公开就要假设所有人都看得到代码。密钥库不在仓库里，所以公开**不会**
> 导致别人能签出你的更新包。

## 7. 本机网络受限时的完整操作清单

`github.com` 被挡时，下列操作全部走 API 脚本：

```bash
PY=C:/Users/admin/.workbuddy-ai/binaries/python/envs/default/Scripts/python.exe

# 推送（增量，自动带父提交）
$PY tools/gh-publish.py --repo MRDOCTOROO/DoobleDouble

# 首次建仓库（私有）
$PY tools/gh-publish.py --repo OWNER/NAME

# 写签名 Secrets
$PY tools/gh-secrets.py --repo MRDOCTOROO/DoobleDouble

# 看 CI 状态
curl -s -H "Authorization: Bearer <token>" \
  https://api.github.com/repos/MRDOCTOROO/DoobleDouble/actions/runs?per_page=3
```

需要 `pynacl`（写 Secrets 用，做 libsodium sealed box 加密）：

```bash
"<managed-python>" -m pip install pynacl
```
